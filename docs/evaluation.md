# 確認手順と試行記録

依頼の違いによって編集の範囲が変わるかを、6件の短い作例で確認します。文章の良さを一つの点数にする評価ではありません。

## 試し方

1. 対象の `SKILL.md` のGitコミット、実施日、使用ツール、利用者側の追加指示を記録します。モデルの設定を指定した場合も、手元の記録に残します。
2. [evaluation-cases.json](evaluation-cases.json) の `request` と `input` を、スキルを読み込んだ会話に渡します。比較する場合は同じ入力・条件を使います。
3. [使用例](examples.md) の出力を見せずに一度実行し、出力を修正せず保存します。再試行した場合は最初の出力と分けます。
4. 各ケースの `checks` に沿って、入力・依頼・出力を照合します。満たす、満たさない、判断保留のいずれかと、根拠になる箇所を記録します。
5. 出力だけを読み、情報を探しにくい箇所や、文のつながりが不自然な箇所が残っていないか確認します。表現が使用例と違うだけでは不合格にしません。

誤字だけのケースは、指定した2語以外が変わっていないかを文字列で比較できます。ほかのケースでは、単語が残っているだけで条件や意味を保てたと判定しないでください。

## この記録の範囲

少数の作例に対する一度の動作確認です。成功率、一般的な文章改善率、他の方法に対する優位性、実務での読者評価は測定していません。同じ入力でも出力は変わり得ます。

[既存の研究記録](methodology.md) とは目的も対象も異なります。この試行結果によって、言い換えや並べ替えを研究で検証済みの自動操作へ追加するものではありません。
